🤖 The Robot That Follows Instructions

Same method as Bug Detectives: Expected vs Actual → Locate → Fix → Verify. Today the “program” is a circuit: two sensors, simple logic, two motors.

Part 1 · The case: Robo-Runner leaves the track

Learners built a line-following robot for the school’s Tech Day. A black tape line is on a white floor. Expected: the robot follows the line to the finish. Actual: it drives straight off the track.

Explain it like I’m 6: A robot is a super-obedient toy. It cannot “see”. It only asks two yes/no questions: “Is my left eye on black?” “Is my right eye on black?” Then it follows its rule book exactly. If the rule book is wrong, the robot obeys the wrong rule.

Learning outcomes: explain sense → decide → act; read and build a truth table; write Boolean expressions; troubleshoot a logic fault using evidence.

Part 2 · Sense → Decide → Act

1 · Sense
Two IR sensors. Output digital: 1 = sees black line, 0 = sees white floor.
2 · Decide
Digital logic (gates) or a microcontroller reads L and R and applies the rules.
3 · Act
Motor driver (e.g. H-bridge) switches the left motor (ML) and right motor (MR) on or off.

The instruction set (the rule book): the line is between the sensors. If a sensor touches the line, the robot is drifting to that side, so it must slow the motor on that side.

LRSituationMLMRRobot does
00Line centred11Forward
10Line drifting left01Turn left
01Line drifting right10Turn right
11Junction / finish bar00Stop
Look closely: read the ML column against L. It is always the opposite. Same for MR and R. So the whole robot brain is ML = NOT L and MR = NOT R: two inverters (e.g. one 74HC04 chip) and a motor driver.

Part 5 · Boss level: Robo-Runner’s bug

Back to the case. The learners’ circuit used ML = L and MR = R (no inverters).

Write the case report: Expected (L=1, R=0 → turn left, ML=0, MR=1) · Actual (ML=?, MR=?) · Evidence · Cause · Fix.

With the faulty wiring and L=1, R=0 the actual output is ML = MR =

Evidence: L=1, R=0 gives ML=1, MR=0, so the robot turns right, away from the drifting line. Cause: the sensor signals were wired straight to the motors instead of through an inverter (NOT gate). Fix: add the NOT stage (or swap to active-low sensor outputs), then verify every row of the truth table. In code: ml = 1 - l.

Same logic in Arduino code (you will build it in Part 6):

int l = 1;            // left sensor: 1 = on black line
int r = 0;            // right sensor
int ml = 1 - l;       // NOT L
int mr = 1 - r;       // NOT R
Serial.print("ML = "); Serial.print(ml);
Serial.print("  MR = "); Serial.println(mr);

Part 6 · Arduino programming: program the robot (Arduino Uno)

Open the Arduino IDE, choose Tools › Board › Arduino Uno and select the correct port. Arduino code is written in C++ (a “sketch”). Every sketch has two parts: setup() runs once, loop() runs forever. Build one block at a time and test each block before moving on (Reproduce → Locate → Fix → Verify).

Explain it like I’m 6: The Arduino Uno is the robot’s brain. A pin is a little door: as an OUTPUT it sends a signal out, as an INPUT it listens. The motor driver is the muscle: the brain whispers, the driver does the heavy lifting.

⚠ Power the motors from their own battery and join its ground to the Arduino GND. Remove the ENA and ENB jumpers on the L298N so PWM speed control works. Some line-sensor modules output 0 on black: check with the Serial Monitor and flip the logic if needed.

Block 1 · Motor driver

const int ENA = 5, IN1 = 7, IN2 = 8;
const int ENB = 6, IN3 = 9, IN4 = 10;

void drive(int ml, int mr, int speed) {   // ml, mr = 1 (on) or 0 (off)
  digitalWrite(IN1, ml); digitalWrite(IN2, LOW);   // left motor forward when ml = 1
  digitalWrite(IN3, mr); digitalWrite(IN4, LOW);   // right motor forward when mr = 1
  analogWrite(ENA, ml ? speed : 0);                // speed 0 to 255 (PWM)
  analogWrite(ENB, mr ? speed : 0);
}

void setup() {
  pinMode(ENA, OUTPUT); pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(ENB, OUTPUT); pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT);
  drive(1, 1, 180);  delay(2000);   // forward 2 s
  drive(0, 0, 0);                    // stop
}

void loop() { }

Block 2 · Ultrasonic sensor

const int TRIG = 11, ECHO = 12;

long distanceCm() {
  digitalWrite(TRIG, LOW);  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH); delayMicroseconds(10);   // 10 microsecond pulse
  digitalWrite(TRIG, LOW);
  long t = pulseIn(ECHO, HIGH, 30000);               // echo time in microseconds
  if (t == 0) return -1;                             // no echo received
  return t * 0.0343 / 2;                             // speed of sound, there and back
}

void setup() {
  pinMode(TRIG, OUTPUT); pinMode(ECHO, INPUT);
  Serial.begin(9600);
}

void loop() {
  Serial.print("Distance: ");
  Serial.print(distanceCm());
  Serial.println(" cm");          // open Tools › Serial Monitor
  delay(200);
}

Block 4 · Put it together: follow the line and stop for obstacles

#include <Wire.h>
#include <LiquidCrystal_I2C.h>

const int ENA = 5, IN1 = 7, IN2 = 8, ENB = 6, IN3 = 9, IN4 = 10;
const int LEFT_S = 2, RIGHT_S = 3, TRIG = 11, ECHO = 12;
LiquidCrystal_I2C lcd(0x27, 16, 2);

void drive(int ml, int mr, int speed) {
  digitalWrite(IN1, ml); digitalWrite(IN2, LOW);
  digitalWrite(IN3, mr); digitalWrite(IN4, LOW);
  analogWrite(ENA, ml ? speed : 0);
  analogWrite(ENB, mr ? speed : 0);
}

long distanceCm() {
  digitalWrite(TRIG, LOW);  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH); delayMicroseconds(10);
  digitalWrite(TRIG, LOW);
  long t = pulseIn(ECHO, HIGH, 30000);
  if (t == 0) return -1;
  return t * 0.0343 / 2;
}

void setup() {
  pinMode(ENA, OUTPUT); pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(ENB, OUTPUT); pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT);
  pinMode(LEFT_S, INPUT); pinMode(RIGHT_S, INPUT);
  pinMode(TRIG, OUTPUT); pinMode(ECHO, INPUT);
  lcd.init(); lcd.backlight();
}

void loop() {
  long d = distanceCm();
  int l = digitalRead(LEFT_S);
  int r = digitalRead(RIGHT_S);

  lcd.setCursor(0, 0);
  if (d > 0 && d < 15) {          // obstacle closer than 15 cm
    drive(0, 0, 0);
    lcd.print("OBSTACLE!   ");
  } else {
    drive(1 - l, 1 - r, 180);         // ML = NOT L, MR = NOT R
    lcd.print("Following   ");
  }
  lcd.setCursor(0, 1);
  lcd.print("L"); lcd.print(l);
  lcd.print(" R"); lcd.print(r);
  lcd.print(" D:"); lcd.print(d); lcd.print("   ");
  delay(100);
}

Notice: the line drive(1 - l, 1 - r, 180) is the truth table from Part 2, written in code.

Part 7 · Exit ticket

Take it to your classroom: seed ONE fault in a working circuit. Ask learners for expected vs actual first, then a truth table, then evidence with a multimeter or LED, then the fix.

⏱ Time limits & scores

A part opens when you press Start. It closes automatically when its time limit runs out, or when you press Finish & score. A closed part cannot be re-opened. Only one timer runs at a time.
